01 — Breakdown

The deposit journey today: 8 steps, one blind spot

KOL link → tradable collateral. Every step has an owner and a real completion test.

01Arrive via KOL linkattribution can silently dropKOL → Project O
02Sign inmethod may not match where funds sitUser + Privy
03Identify funding source“which wallet has the money?”User
04Get funds + gas on Arbitrumno gas token on the destination chainUser + bridge / CEX
05Approve token spenddefaults to unlimited allowanceUser + contract
06Submit deposit tx → receiptreceipt ≠ usable funds — the trapUser + provider
07Collateral reflected on Hyperliquidreal delay, zero visibility todayExternal provider
08User sees “ready to trade”silence reads as failure → re-depositProject O
The friction zone
A receipt is not credited collateral. Today steps 6→8 are silent — so “still bridging,” “no gas,” and “failed” all look identical. Users assume failure and re-deposit.
Steps 2 · 3 · 7 can each be a different wallet — nothing labels which is which submission.md §1
02 — Prioritisation

Why this is the single biggest friction point

Not one of several equally-good options — four independent reasons.

01
The brief itself names it
“Complete only when tradable collateral is reflected — not when a receipt is issued.”
02
Documented in the wild
Third-party “deposit stuck” guides exist. Their first instruction: “do not send a second deposit.”
03
Hits exactly this audience
Korean CEX withdrawers, KOL-referred, mobile — least equipped to read ambiguous silence.
04
It causes financial harm
Duplicate deposits cost real money. Cosmetic friction only costs conversion.
Considered and rejected as the primary fix: sponsored gas (infra beyond PoC, and the gap remains) · wallet unification (explicitly out of scope — label, don’t merge) · cutting funnel steps (no real data — that would be a guess).
03 — The fix

Deposit Reconciliation Engine

A real backend state machine — persistent records, not a UI illusion.

SIGNED
→
CONFIRMED_ONCHAIN
→
BRIDGING
→
CREDITED
STALLED_NO_GAS
STALLED_TIMEOUT
AMBIGUOUS
CREDITED needs both sides to agree: the real on-chain receipt read via RPC (never trusting the client) and the Hyperliquid balance signal.
Disagree past the window → flagged AMBIGUOUS for investigation. Never a forever-spinner, never a silent retry.
Duplicate-deposit block: a second deposit for the same wallet + amount while one is in-flight is refused with a link to the live status. Verified on testnet — HTTP 409.
Live status tracker · real app
04 — Five UX layers

One root cause, five surfaces

Not five unrelated patches — every layer attacks state opacity.

LAYER 01 Exact-amount approval Unlimited allowance is opt-in and honestly labelled — never the default.
LAYER 02 Plain-language failures “You don’t have enough ETH to pay the network fee” — zero crypto background assumed.
LAYER 03 Full address confirmation Never truncated, with an explicit lookalike-address warning. Address poisoning is real.
LAYER 04 Wallet-role labelling “Signing in as / Funds coming from / Will be tradable in” — never a bare “your wallet.”
LAYER 05 KOL disclosure Persistent, compliance-grade: Exchange O is independent — the decision is yours alone.
All five ship in the live PoC. The approve screen alone carries three of them — roles, plain-language gas failure, and approval scope — on one mobile viewport.

07 — Measurement

How we’d know it worked

Primary metric
% of deposits reaching CREDITED without a re-deposit attempt or a support contact
Targets the two named failure modes directly — not a generic conversion rate this fix only influences.
Guardrails — must not regress
Time-to-CREDITED p50 / p90
A rising p90 is an infrastructure signal, not a UI one.
AMBIGUOUS rate
Rising means reconciliation genuinely disagrees more often. Investigate — don’t extend the timeout.
Duplicate-block rate
A spike means the status UI isn’t reassuring users fast enough about their first deposit.
Not available, and not invented: real funnel drop-off, support-ticket volume, and the true production time-to-credit distribution. The brief withholds them by design.
08 — Honest close

What’s mocked, and what’s next

Known limitations
  • No real database — in-memory store; record loss observed live, not theorised
  • Hyperliquid credit is a timer, not a real balance read
  • Mock ERC-20, not Circle testnet USDC
  • Mocked login; no human MetaMask click-through yet
Before production
  • External store — fixes lookups and cross-instance duplicate blocking
  • Real Hyperliquid balance integration
  • Re-verify the live deposit rail — the legacy bridge is deprecated
  • Calibrate AMBIGUOUS thresholds on real bridging latency
  • Sponsored gas for the no-ETH dead-end
Every mock is labelled in the UI itself — including the failure screen when the PoC loses its own record.
